The speedup comes from amortising thread management overhead and allowing the CPU to interleave work across images. Gains are modest (22\% from 1 to 20) because the bottleneck---image warping---already parallelises efficiently for a single pair.

\section{Accuracy vs Speed}

Two peak-finding algorithms trade accuracy for speed. The gap comes from cross-correlation (gauss6 fits a more complex model per window) and infilling (biharmonic solves a PDE, local median uses a fast neighbourhood filter).

\section{How the Pipeline Works}

Each image pair is processed through three multi-grid passes:

\begin{enumerate}[leftmargin=1.4em]
\item \textbf{Pass~1 (64\,px windows):} Cross-correlate the raw images to get a coarse velocity estimate on a 63$\times$63 grid.
\item \textbf{Pass~2 (32\,px windows):} Warp both images using the Pass~1 estimate, then cross-correlate the warped images on a finer 127$\times$127 grid.
\item \textbf{Pass~3 (16\,px windows):} Warp using the Pass~2 estimate, cross-correlate on the finest 255$\times$255 grid.
\end{enumerate}

After each pass, outlier detection removes spurious vectors and gap filling replaces them from neighbours. The image warping step uses a custom C library that fuses predictor interpolation, symmetric coordinate mapping, and bicubic image sampling into a single parallel loop---roughly 3$\times$ faster than the standard OpenCV pipeline.

\section{Key Takeaways}

\begin{enumerate}[leftmargin=1.4em]
\item \textbf{85\,ms per pair} at 4\,MP (fast) or 138\,ms (accurate), with 4 CPU threads.
\item \textbf{501\,ms per pair} at 25\,MP---the pipeline scales linearly with pixel count.
\item Image warping is the dominant cost (53\% of the finest pass), because it must touch every pixel in the image.
\item Larger batches help modestly: 22\% faster at 20 pairs vs 1 pair.
\item The choice of peak finder has a bigger impact than batch size: gauss6 adds 53\,ms per pair (62\% slower) compared to gauss3.
\end{enumerate}
